# Evidencia T03 · PostgreSQL y migraciones

Fecha: 2026-10-21. Entorno: Docker Compose local con PostgreSQL 18 y Python
3.12 mediante `uv`.

## Migración y catálogo

Se creó `inflacion_lab_test`, una base separada de desarrollo. Después de
ejecutar `alembic downgrade base`, `make test-db` aplicó
`alembic upgrade head` sobre la base vacía. La suite volvió a ejecutar la
migración y confirmó las siete tablas, por lo que repetir `upgrade head` no
modificó el esquema.

En la base de desarrollo se ejecutó dos veces:

```bash
DATABASE_URL_MIGRATIONS=postgresql+psycopg://.../inflacion_lab \
  uv run --locked inflacion-lab catalogo registrar
```

Ambas ejecuciones informaron 88 geografías, nueve rubros y 792 series. La
consulta posterior devolvió `88|9|792`.

## Persistencia

Después del registro se ejecutó `docker compose down` y luego
`docker compose up --detach postgres`, sin la opción de borrar volúmenes. La
misma consulta devolvió `88|9|792`. El volumen declarado es
`postgres_data:/var/lib/postgresql`, la ruta requerida por PostgreSQL 18.

## Verificación ejecutada

```text
make test       # 14 passed, 3 deselected
make test-db    # 3 passed, 14 deselected
```

La integración comprueba conservación de `Decimal` con seis posiciones, nulos,
restricciones de periodo y valor, la FK compuesta de revisiones y la carga
idempotente del catálogo. La validación de `TEST_DATABASE_URL` se ejecuta antes
de que el fixture invoque Alembic; una URL cuyo nombre no termina en `_test`
lanza `ConfigurationError` en la suite unitaria.
